# emthin terminal gateway v1

This contract supplies the wire and state-machine decisions for
[T11–T14](HERDR_INTEGRATION_PLAN.md#t11-fixture-the-scoped-gateway-protocol)
and the fleet methods for T18. The [integration specification](HERDR_INTEGRATION_SPEC.md#h5-pairing-transport-and-access)
defines which sessions are eligible. The gateway has its own API and uses
Core generation 1 upstream. It reuses the Core frame envelope.

## Pairing and listeners

- The QR text is `https://<host>.<tailnet>.ts.net/pair?v=1&core=<core-id>`.
  Scan and Paste use the same parser. Allow only an HTTPS hostname made of
  DNS labels below `ts.net`, default port or 443, the exact `/pair` path,
  and one occurrence of each expected query parameter. Reject credentials,
  fragments, IP literals, unknown parameters and links over 1 KiB. Treat
  the URL as data and construct the requests below on its origin. Follow
  zero redirects.
- Accept remote management and stream access on the TLS tailnet listener.
  Determine the peer from tsnet WhoIs on the connection's actual
  remote address. Require the owner user ID and untagged node identity.
  Use a private registry keyed by stable node ID, user ID and Core ID.
  Check the rights attached to that grant for every operation. A local
  Unix listener uses checked owner UID and its configured scopes instead.
- Pairing requests and responses are bounded JSON over HTTPS with
  `Cache-Control: no-store`. Host approval uses a separate owner-only CLI
  channel. The QR carries no bearer secret. The request ID tracks a
  request for the same verified node and has no authorization by itself.

| Endpoint | Request | Successful response |
|---|---|---|
| `POST /v1/pair` | `{"version":1,"core_id":"<core-id>"}` | 202 and `{"request_id":"<id>","state":"pending","expires_in_s":300}`. Repeat POST returns the outstanding request and remaining lifetime. A current grant returns 200 and `{"state":"approved","core_id":"<core-id>"}`. |
| `GET /v1/pair/<id>` | Same WhoIs principal as POST | 200 with `{"state":"pending","expires_in_s":298}`, `{"state":"approved","core_id":"<core-id>"}` or `{"state":"denied"}`. An expired or unknown request returns 404. |
| `GET /v1/stream` | TLS WebSocket upgrade, subprotocol `emthin-terminal.v1`, active grant | 101. Reject browser Origin headers and other subprotocols. Use the current node grant to authorize the socket. |

HTTP errors use `{"error":{"kind":"core_mismatch"}}` with a bounded optional
human message. Use 400 for bad syntax/version, 403 for denied or missing
identity/grant, 404 for missing pairing requests, 409 for the wrong Core
ID, 429 for throttling and 503 when Core identity is unavailable. A
request for another node's pairing ID gets the same 404 as an unknown ID.
An approval stores the grant before returning success. Clients poll every
two seconds while the pairing view is open and stop on close, expiry or
a terminal response. Revocation also clears outstanding pairing requests
and closes that node's streams and leases.

## Frames and handshake

Every frame begins with `channel:u32LE | kind:u8 | length:u32LE`. A
WebSocket message contains exactly one frame after fragmentation is
reassembled. Unix connections read the same frames directly and must
handle split headers/payloads and short writes. WebSocket control frames
are handled by the WebSocket library. Write one frame at a time. After the
transport opens, wait up to five seconds for the channel-zero hello.
Apply upgrade and message limits before buffering a full message.

| Channel | Kind | Payload and direction |
|---|---|---|
| 0 | 0 DATA | One UTF-8 JSON-RPC object. Client sends requests with positive u32 IDs unique among outstanding calls. Gateway sends replies and notifications. |
| >0 | 0 DATA | Server output bytes for either mode, or client input bytes for a live controller. |
| >0 | 1 CREDIT | Client to server, four bytes u32LE. Replenishes consumed server DATA only. |
| >0 | 2 CLOSE | Client to server with empty payload. Server to client with UTF-8 JSON reason, including `{"reason":"detached"}` for acknowledgement. |
| >0 | 3 RESIZE | Two u16LE values in cols/rows order. Controller to server, observer from server. |
| >0 | 4 FOCUS | Controller to server, exactly one byte with value 0 or 1. |
| >0 | 5 FACTS | Controller to server, JSON with optional Core fields `fg`, `bg`, `cursor` and `cell`. |
| >0 | 6 AUTOMATIC_INPUT | Controller to server when confirmed for this attach. Raw bytes generated by the VT client. |

Use strict object decoding for requests. Reject duplicate keys, arrays
of requests, wrong types and fields outside the method's schema. A
well-formed but unknown method receives JSON-RPC `-32601`. Keep response
and notification decoders tolerant of additive well-formed fields. Use
the standard parse/invalid request/invalid params error codes for control
syntax. Application errors use `-32000` with stable `error.data.kind`.
Known kinds include `core_mismatch`, `core_offline`, `unsupported`,
`not_found`, `forbidden`, `in_use`, `stale_generation`,
`stale_revision`, `expired`, `busy` and `needs_reconciliation`.
Address-based calls return the same `not_found` for an absent terminal
and an unenrolled one. Use `forbidden` for a known visible target with
insufficient action rights.

Examples below use `6ab09a20fd1288983dfbbac2bb349231` as the fixture Core
ID. These are separately framed messages.

~~~json
{"jsonrpc":"2.0","id":1,"method":"hello","params":{"version":1,"core_id":"6ab09a20fd1288983dfbbac2bb349231","features":["resize_notifications","automatic_input"]}}
{"jsonrpc":"2.0","id":1,"result":{"version":1,"core_id":"6ab09a20fd1288983dfbbac2bb349231","features":["resize_notifications","automatic_input"],"methods":["hello","sessions.list","terminal.attach","control.request","control.respond"]}}
~~~

The hello checks the expected Core ID against the current local Core and
negotiates the declared features. The client sends hello once. The
gateway closes on mismatch, invalid protocol version or failed
authentication. A Core connection loss invalidates all mappings on that
gateway connection and closes it. Reconnect verifies identity and
rebuilds the catalogue. Backends advertise fleet methods only when the
configured integration supports them.

## Catalogues and attach

All method params in the following tables are object fields. Required
fields are named directly. A question mark marks optional fields.
Generations, revision tokens, reservations and handoff IDs are opaque
strings. Compare them for equality. Discard all connection-owned state
on reconnect, including catalogue revisions and channel IDs.

| Method | Params | Result |
|---|---|---|
| `sessions.list` | `if_revision?`, `cursor?`, `limit?` (default 32, max 64), `addresses?` (up to 8 exact local addresses) | `{revision, rows, next_cursor}` with null cursor on the final page. Same revision on a first-page refresh permits `{revision, unchanged:true}`. A cursor binds the request scope, address filter and revision. Return `stale_revision` if pagination crosses a change. |
| `terminal.attach` | `address`, `generation`, `mode` (`watch` or `control`), `history?` (default 200, max 1000), `grid?`, `display?`, `reservation?` | `{channel, mode, generation, grid, resize_notifications, automatic_input, lease_id}`, with null lease ID for a watcher. Return success before any channel frames. |

A row includes `address`, `generation`, `label`, `grid`, `lifecycle`,
`status` and `actions`. Core ID comes from the connection hello. Grid
is `{cols,rows}`, with positive integers up to 300 and 120 respectively.
A finished row may have null grid. An out-of-budget grid is also
represented by null, with a `grid_unsupported` reason and no watch action.
Lifecycle is `live`, `lost`,
`finished` or `starting`. Status is null for no report or a bounded
`{state,detail}` projection of the Core report. Actions derive from
effective rights and current state, using `watch`, `control`, `stop`.
Bound labels and each status string to 256 UTF-8 bytes and allow normal
terminal output only on the data channel. Unknown status words can be
displayed as text. They drive no client control behavior.

Only controller attach accepts `grid` and `display`. Controller attach
requires a grid with at least 20 columns and 5 rows. A watcher uses the
upstream authoritative Core grid. If it falls outside the local scene
budget, fail the attach with `unsupported`. If a subsequent resize
exceeds it, close the stream with reason `grid_unsupported`. Require
confirmed Core resize notifications for watcher attach, and deliver its
initial RESIZE before its first DATA. Confirm automatic replies only
when hello and attach support them across the path. Leave legacy reply
fallback under the controller's Core compatibility behavior.

Gateway emits `sessions.changed` with params `{revision}`. Coalesce
hints by replacing any queued, unsent hint for the same connection.
Never emit an update triggered solely by hidden inventory. Fetch a
replacement on a changed revision, reconnect or screen foreground. If a
page becomes stale, discard the pending page collection and restart at
its first page. Continue showing the last complete catalogue while
refetching. A change to label or status preserves the program
generation. A lost/restarted event, Core connection replacement, or a
missed event range that might hide a replacement invalidates affected
generations and closes old control channels. Program generations
are gateway-issued, based on observed lifecycle, without relying on
Core's private `program_started_ms`. No control request survives an
invalidation.

For fixture address `t3` and generation `g-fixture-1`:

~~~json
{"jsonrpc":"2.0","id":2,"method":"terminal.attach","params":{"address":"t3","generation":"g-fixture-1","mode":"watch","history":0}}
{"jsonrpc":"2.0","id":2,"result":{"channel":7,"mode":"watch","generation":"g-fixture-1","grid":{"cols":80,"rows":24},"resize_notifications":true,"automatic_input":false,"lease_id":null}}
~~~

| Fixture frame | Hex bytes |
|---|---|
| Channel 7 RESIZE 80 x 24 | `07 00 00 00 03 04 00 00 00 50 00 18 00` |
| Channel 7 DATA CAN followed by `OK` | `07 00 00 00 00 03 00 00 00 18 4f 4b` |
| Channel 7 CREDIT for those three bytes after parser consumption | `07 00 00 00 01 04 00 00 00 03 00 00 00` |
| Channel 7 client CLOSE | `07 00 00 00 02 00 00 00 00` |

## Ordering and bounds

- Gateway allocates strictly increasing channel IDs on the socket and
  maps them to an upstream connection/channel pair. Overflow requires a
  reconnect. Commit the mapping and write the attach response before
  releasing its queued data. Associate queued input with the connection,
  grant, channel, lease and program generation. Validate those owners
  again on upstream write. For a completely closed channel on the same
  socket, discard delayed frames without reaching Core. Unexpected IDs
  that were never allocated are protocol violations.
- Use one end-to-end output window of 256 KiB per attach. Its implicit
  upstream and downstream initial budgets correspond to the same bytes.
  Track bytes received upstream, bytes committed to downstream transport
  and bytes credited by the client. Only accept positive CREDIT up to the
  sent-but-uncredited byte count and forward it once to Core. Never grant
  credit prematurely to keep a stalled view alive. The 4 MiB repaint
  threshold stays in Core. Preserve DATA/RESIZE order and CAN. Do not
  rebuild stalled output in the gateway. A failed stream requires a
  fresh attach. Keep program-end CLOSE after already accepted output.
  Administrative CLOSE on revoke, release or overflow discards its
  pending output.
- Keep Core's 16 MiB wire ceiling as an absolute bound. On the gateway
  leg use 64 KiB control payloads, 16 KiB terminal DATA/input chunks,
  1 KiB FACTS or CLOSE JSON, 8 attachments per connection and 32
  outstanding control calls. Split larger upstream DATA into ordered
  chunks and never split an individual control/resize/CLOSE frame.
  Keep per-channel terminal output within the credit window plus a
  bounded queue of 32 non-DATA frames. Start with a host limit of 64
  attachments and 4 MiB queued control data across all sockets. Downstream
  input is not Core DATA credit. Queue at most 64 KiB of input/control
  per controller to Core and rate limit input to a sustained 64 KiB/s
  with a 64 KiB burst. Android splits paste into chunks without
  reordering or replay. On excess input close and report the interrupted
  paste/stream. Do not silently truncate or synthesize remaining bytes.
- Fair scheduling gives control work service between stream batches.
  A channel at zero credit does not block other channels. A socket
  unable to complete writes for ten seconds closes and drops all its
  leases. WSS pings every 20 seconds on idle, with an unanswered ping
  timed out after ten more. Unix EOF ends the session. A structurally
  invalid header/message closes the connection. A valid envelope with
  invalid mode, credit or stream payload closes the responsible channel.
  Notifications remain advisory. Clients do not infer authorization
  from receiving an old catalogue row.

## Control handoff and lifecycle

| Method | Params | Result and transition |
|---|---|---|
| `control.request` | `address`, `generation` | `{handoff_id,expires_in_s:30}`. Requires control rights and a busy target. One pending handoff per terminal. Notify the current controller via `control.pending` with address, current lease ID, handoff ID, expiry and verified requester display label. |
| `control.respond` | `handoff_id`, `lease_id`, `accept` | The current controller only. Return `{state:"accepted"}` or `{state:"denied"}`. On accept, revoke the old writer, enqueue its CLOSE, fence its upstream input and reserve attach for the same requester connection for 15 seconds. Tell the requester via `control.result` with handoff ID, state and reservation when accepted. |
| `session.stop` | `address`, `generation`, `request_id` | `{state:"stopped"}` only after the host adapter verifies termination. Repeated same request returns its recorded result. An uncertain stop returns `needs_reconciliation`. |
| `fleet.status` | `{}` | `{profiles:[...]}` with explicitly visible profiles using the projection below. |
| `fleet.launch` | `profile`, `slot`, `request_id` | `{state:"live",address,generation}` after admission or reuse of the verified live slot. An unresolved attempt returns `needs_reconciliation`. |

Store lease transitions and input forwarding in one serialization
domain per terminal. A pending attach reserves the controller slot until
the upstream result is known. On handoff or disconnect, block future
input writes from that lease, drain a write already started to Core and
close its upstream channel before activating the next writer. On
uncertain upstream write or teardown, release both streams and require a
fresh attach. Bytes already committed to the PTY can still execute.
Reservation is single-use and bound to the requester connection and
program generation. A reservation expires on 15 seconds, disconnect,
revocation or generation change. On denial, cancellation, requester
timeout or controller voluntary release, clear the handoff and notify
the requester. Voluntary release allows the requester to acquire again
through normal attach. Client-side “Take control” stays explicit.

For launch/stop, `request_id` is a client-generated UUID scoped to
principal and method. Persist pending and final state and bind the ID
to its validated operation arguments. Reject reuse with different
arguments. Return `busy` while an equivalent request is running and
`needs_reconciliation` when host outcome is incomplete. Launch accepts
only IDs selected from the server's configured profiles. Stop requires
a separate right, a matching generation, a confirmed target without
automatic replacement and a working targeted teardown path. Hold
the slot operation lock through verification and persistence.

A profile row is `{profile,label,readiness,slots,disk_sharing,memory_sharing}`.
Readiness is `ready`, `starting`, `unavailable` or `unknown`. A slot row
is `{slot,label,state,can_launch,address}`. State is `empty`, `starting`,
`live`, `finished` or `needs_reconciliation`. Address is null without an
enrolled record visible to this device. `can_launch` expresses effective
launch rights and current readiness. Each sharing field is
`{state,checked_at_ms}`. State is `configured`, `verified`, `unavailable`
or `unknown`. Time is null without a measurement. Verified evidence
belongs to a deployment identity and resets when the VM, driver, closure
or active mounts change. Detailed measurements are available to the host
operator. IDs are 1–64 ASCII characters from letters, digits, underscores
and hyphens. Never interpret them as file paths.

## Fixture matrix for implementation

| Case | Observable result |
|---|---|
| Stream opened by unknown, revoked or tagged node | Upgrade denied. Local Core receives no call. |
| Pair repeated by one node, then polled by a different node | Same pending ID for the first node. Generic 404 for the second. |
| Hello plus attach coalesced on Unix | Hello completes before attach. Both frames survive buffered reads. |
| Request contains an arbitrary Core method, machine address or unexpected property | Deterministic validation error. No Core passthrough. |
| Two page requests straddle a catalogue replacement | Cursor becomes stale and the client starts a replacement set. The current rendered set stays usable. |
| Watch channel sends DATA, FOCUS, FACTS or RESIZE | Watch channel closes. Input never reaches the PTY. |
| Watcher sends duplicate credit or changes focus while credit is zero | Invalid stream closes. A second credited terminal still updates. |
| Watcher starves, then resumes after Core produces a replacement paint | Parse charged old bytes, then ordered RESIZE and CAN repaint. New grid and screen match the fixture. |
| Grant revoked or program changes during a live handoff | Old owner cannot write after the fence, reservation fails and reconnect starts as watch. |
| Program finishes while a visible observer still has output outstanding | Deliver final bounded DATA before normal CLOSE, or expire the stalled stream. |
| Retry after loss between host launch and receipt of reply | Reconcile slot and Core record. Return its existing identity or `needs_reconciliation`. No second process. |
| Host CLI exits but guest workload remains | Stop stays unverified. Other workloads and VM are unaffected. |

Commit the JSON examples and binary frame vectors as machine-readable
test inputs in T11. Go gateway and Rust client tests use the same
fixtures. Real pairing, fleet and renderer results belong to the
[integrated acceptance run](HERDR_ACCEPTANCE_RUN.md).
