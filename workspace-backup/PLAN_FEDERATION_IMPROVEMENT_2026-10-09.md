# Federation review & improvement plan — 2026-10-09

Scope: the seven sibling repositories under `~/Projects/` —
`unfer`, `australVM`, `velysterm`, `timepiece`, `dynamic-arctic`, `test`,
`emthin` — plus a disk-space pass. Lean4 source is explicitly out of scope
(that is the Lean4 specialist's surface); every finding below is in tooling,
documentation, build configuration, or non-Lean code.

Method, per repo: run the repo's own documented verification gates, run the
family checkers it ships (`scripts/verify-invariants`, `scripts/check-status`,
`scripts/check-gitbook-drift`, `scripts/check_site.py`), then audit the claims
its docs make against what the tree and the tools actually do.

### 2.1 `dynamic-arctic` — the paper reproduction was unreachable

* `repro/repro_fig7a` called `../target/release/arctic` with positional args
  (`n t Cs nsigs`). That binary is now the AT-Protocol authority, whose CLI
  takes flags and rejects positionals — confirmed by running it:
  `arctic: unexpected argument "3"`. Upstream's benchmark harness still exists
  here as `arctic_bench` and takes exactly those arguments, so the script was
  one word from working. Fixed; verified by running the script's own command
  line, which prints a datapoint.
* `README_arctic.md` documented `./repro-fig7a` (hyphen) while the file is
  `repro_fig7a` (underscore), and documented Figure 7b's `repro-fig7b` and the
  `rayon` branch — neither is carried in this fork. Both now marked.
* `docs/RUNBOOK.md`'s endpoint table omitted `POST /api/v1/messages`, which the
  router serves (and the tests exercise); its `/version` example contradicted
  the documented `threshold`/`total_nodes` defaults (2/3 vs 3/7).
* `README.md`'s closing disclaimer claimed "32 passing unit tests" — matching
  neither the 19 library tests nor the 66 full-suite count.
* `src/config.rs`: `apply()`'s doc comment was stranded on `scalar_to_string`.

Verified: `cargo fmt`, `clippy -D warnings`, `cargo test --all-features`
(19 + 47 = 66), `cargo test --no-default-features --lib` (19).

### 2.2 `test` — a checker that could not see its own drift

`README.md` advertised "61 pages, 284 links, 218 pairs, 2 orphans" while the
tree had 62 / 286 / 219 / 17. The checker inspects the link graph, so no amount
of link checking could catch a stale count.

* Added a status census: `scripts/check_site.py` now reads both the
  `<!-- status: ... tests: N pages / M links ... -->` marker and the quoted
  `[info]` transcript and warns when either disagrees with the tree. It warns
  rather than fails, because the documented exit contract is "1 on SUMMARY
  drift or broken links" and silently widening it would fail CI on changes that
  are otherwise correct.
* `AGENTS.md` and `ATTRIBUTION.md` are excluded from the orphan set. They are
  router files that prose never links to, so the permanent "2 orphan page(s)"
  warning was noise that would have masked a real orphan.
* The quoted transcript is now byte-identical to real output (verified by
  diffing the fenced block against an actual run).

Verified: exit 0, SUMMARY consistent, no broken links; negative control (a
temporarily stale marker is reported).

### 2.3 `velysterm` — dead links inherited from replayed upstream docs

`README.md` reproduces upstream `voxell-tech/velyst`'s README and carried over
its `./examples/{hello_world,center_box,game_ui}.rs` pointers. This fork has no
top-level `examples/*.rs`; the demo ships under `examples/velyst_demo/`. Six
links (three in `README.md`, three in `README_velyst.md`) were dead; they now
point at the Typst assets that actually ship, with a header marking the section
as upstream's.

Verified: all 14 relative links across `README.md`/`README_velyst.md`/
`AGENTS.md`/`CHANGELOG.md` resolve (0 broken); `cargo fmt --check` and
`cargo clippy -p mathed_core --all-targets -- -D warnings` clean.

### 2.4 `australVM` + `timepiece` — false failures from absent tooling

This is the most consequential finding: **both repos' `verify-invariants`
exited 1 on a machine that merely lacked an interpreter.** A gate that is red
for an environmental reason is worse than no gate, because a genuine failure
becomes indistinguishable from "no tool here".

* `australVM`: the H2 symbol-census gate called `python3` unconditionally →
  `[FAIL] H2: unfer symbol census in sync with SYMBOL_REGISTRY`. Added
  `check_py()`, mirroring the pattern `unfer/scripts/verify-invariants` already
  used.
* `timepiece`: `[FAIL] gitbook drift` (no python3) and
  `[FAIL] lake build BookProof Singularity Layout`
  (`error: command failed: 'lake'`). Both are now explained gaps. The `lake`
  probe is **executability** (`lake --version`), not presence: an elan shim can
  be on PATH while the toolchain it dispatches to is not installed, so
  `command -v lake` succeeds and the gate fails anyway.

Verified in both directions — this is the part that matters:
* tools absent → `australVM` 18 passed / 0 failed (was exit 1); `timepiece`
  5 passed / 0 failed / 2 gaps (was exit 1). `TIMEPIECE_SKIP_LAKE=1` still
  short-circuits.
* tools present → the checks **run and still fail on real drift**:
  `australVM` `[pass] H2: unfer symbol census in sync` (19 passed), and
  `timepiece` correctly reports
  `[MISS lean] ym_h_essentiallySelfAdjointOn` cited by
  `proofs/qym-sm-enclosures.md` — a genuine stale citation. The assertions are
  unchanged; only the false failure is gone.

### 2.5 `emthin` — verified with a command that cannot work as written

The "Local verification" block listed four bare `cargo` commands. Outside
`nix develop` every one dies at
`error: failed to run custom build command for glib-sys v0.20.10`, because
`emthin → emthin-dbus → gio/glib` resolves glib via `pkg-config` at
build-script time and only the devshell supplies it. `docs/build-notes.md`
already explained this; the command list did not. Now stated where the commands
are, with the mechanism.

Verified: `nix develop -c cargo fmt --all -- --check` exit 0;
`nix develop -c cargo test -p emthin` compiles glib-sys and passes
(236 + 15 + 5 tests, 0 failed).

## 3. Cross-cutting findings (not yet fixed — recommended work)

Ordered by value. These are improvements to existing machinery, not new
features.

### P1 — `check-status` verifies presence, not truth

`unfer/scripts/check-status` walks all seven repos and reports `ok` for every
status block, including `australVM`'s "110 dune / 14 suites" and `emthin`'s
"310 cargo". It explicitly does not check that the counts still match — a
weakness `dynamic-arctic`'s own README documents ("This line was stale at 62
until 2026-10-05 … it drifted silently"). The `test` repo has now been given a
census check (2.2); the same pattern generalises. **Suggested:** extend
`check-status` to re-run each repo's fastest test command and diff the count
against its marker, reporting mismatches as warnings. This is the single
highest-leverage change in the federation, because it closes the drift channel
for all seven repos at once.

### P2 — upstream READMEs replayed without a fork boundary

Three repos embed another project's README as a live document
(`dynamic-arctic/README_arctic.md`, `velysterm/README{,_velyst}.md`) and
inherit its dead links, wrong binary names, and absent branches. Two were fixed
by hand here. **Suggested:** adopt a `README_UPSTREAM.md` convention for
replayed upstream text, so fork instructions and upstream text can never be
confused, and add the family link checker to CI for all repos (only `test` has
one today).

### P3 — environment prerequisites are not where the commands are

Both failures in 2.5 and, in spirit, 2.4 come from prerequisites documented
somewhere other than the command list. `velysterm` needs `libudev`/
`pkg-config` under `nix develop` for `mathed`; `emthin` needs the devshell for
the whole workspace. **Suggested:** every repo's "verify" block should be
copy-pasteable in a clean shell, with the devshell baked into the command
(`nix develop -c …`) rather than described in prose.

### P4 — spent one-shot generators left on disk

Found three: `verifiedUniqueAliases/patch.js` (removed, commit `652d95e` — it
wrote a stale 43 KB copy of `main.rs` and a pre-fix `verify.html` through a
dead absolute path), `unfer/patch_ops.cjs` (same class: inserts `decide_*` ops
into `unfer_protocol/src/ops.rs`; the ops are already present at lines 104-107
and 247-250, so it is spent), and `velysterm/crates/kernel_client/scripts/*`
(legitimate, documented). `patch_ops.cjs` is **untracked**, so it is not
recoverable and was left in place — a judgement call, not an oversight.
**Suggested:** delete it, or `git add` it if it is wanted as provenance.

### P5 — undocumented-but-present surfaces

`dynamic-arctic` had two bench binaries and a repro script reachable from no
agent-facing doc (now documented). The same audit has not been run on
`australVM` (120 `.ml`/`.mli`, 348 `.aum`) or `timepiece` (a large
`scripts/` toolset: `board_rollup.py`, `doc_index.py`, `import_components.py`,
`split_module.py`, `propose_split.py`). **Suggested:** list each repo's scripts
and entry points in its `AGENTS.md`, and check that each is referenced.
